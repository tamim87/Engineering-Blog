# Writing guidelines

Articles should be based on real experience.

## Prioritize

- concrete technical explanations and useful examples
- clear reasoning and stated trade-offs
- failures and debugging stories
- practical lessons

## Avoid

- generic filler and meaningless introductions
- exaggerated claims and fake expertise
- buzzword density
- motivational language
- claims about work you cannot show or describe accurately

## Practices

- State the problem and context first; say what was tried and what happened.
- Show real code or commands, and say which versions were used.
- Note when something may age (framework versions, defaults).
- Confidential employer work: describe general lessons only, without
  confidential details.
- Every article needs complete metadata (see the content model) and a
  description that says what the reader will learn.
- One idea per article; use `series` for multi-part topics.
